## Current implementation

The internal budget owner validates finite integer limits at or below SEC-5 ceilings. Redirects default to disabled, with at most three when explicitly configured. A logical retrieval retains wire/decoded counters, redirect count and a monotonic total deadline across caller-owned attempts. An additional 32-attempt admission ceiling limits empty/fast responses; it is not a retry schedule or permission to retry effects. First failure is stable and aborts the signal owned by downstream I/O. Read inactivity is separately started/reset only during response work. Timers and external cancellation listeners are released on close/failure. The caller must close the budget in its operation's finally block.

The stream reader counts raw response-body bytes before decoding and decoded bytes before retention. It supports identity or one native gzip/deflate stage; unsupported/stacked encodings and corrupt/truncated streams fail closed. Pipeline cancellation destroys its owned streams. Small input chunks are packed into 64 KiB slabs so metadata allocation is bounded; output construction has bounded copies, not an unbounded array of one buffer per attacker byte. No syntax parsing, response/header projection, durable storage or logging occurs here.

The HTTP owner now sends only a code-owned GET over the #97-approved TLS socket, with a fresh single-use agent that cannot create another connection. Native strict HTTP parsing and a 16 KiB header limit remain active; the complete header list is limited to 100 fields, selected singleton duplicates are rejected, and unsupported transfer/content codings, informational upgrades and trailers fail closed. Only a bounded content type, status, body and typed provider wait cross the internal result boundary; no arbitrary response headers, raw errors or provider bodies from unsuccessful status results are copied into outcomes.

Explicitly enabled redirects repeat the destination/authority/DNS/TLS path and share the original counters and deadline; no credentials or caller-supplied headers are accepted or forwarded. Provider wait facts survive a corrupt response body, are immutable when retained, and prevent early repeated reads in the same operation. Missing/invalid timing remains unknown rather than inventing a retry delay. There is no automatic retry/sleep or effectful request method. A per-transport cap admits at most four logical operations; concurrent reads of one operation are rejected. Global transport admission and durable provider scheduling remain owner integration work.

Monotonic checks complement timers before accepting chunks, creating subsequent work and returning a body. A direct regression probe of the prior budget accepted bytes with zero time remaining after its timer was delayed; the new tests deliberately block the event loop and prove rejection, cancellation and no late success. The companion #97 fix rejects overdue DNS before creating a socket.
