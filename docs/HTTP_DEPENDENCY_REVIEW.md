# HTTP boundary dependency review — 2026-11-05 UTC

## Selection and maintenance

`fastify` **5.12.8** is the architecture-approved framework. Native HTTP supplies framing but not the selected routing/schema lifecycle. The [official release](https://github.com/fastify/fastify/releases/tag/v5.12.8), tagged package, [live registry](https://registry.npmjs.org/fastify/5.12.8), publisher Matteo Collina and upstream team agree. The November 2 security release is recent: its timeout patch and actual published implementation were inspected, rather than treating recency as assurance. The tagged CI matrix includes Node 20/22/24/26. This adds a substantial, expected framework tree, including Ajv, response serialization and logging dependencies. No optional plugins are added; logging remains unconfigured pending Wave 0. Only code-owned schemas may reach the framework's reviewed compilation exception. Actual Linux compatibility still requires CI.

Add `jsonc-parser` **3.3.1** for duplicate-aware JSON validation. Native `JSON.parse` discards repeated member names; a replacement JSON grammar would increase correctness and maintenance risk. Microsoft's [tagged source/API](https://github.com/microsoft/node-jsonc-parser/tree/v3.3.1), [registry](https://registry.npmjs.org/jsonc-parser/3.3.1), Microsoft/vscode publisher and maintainer accounts agree. Stable 3.3.1 remains latest; 4.0.0-next.2 is prerelease. There are no runtime dependencies. The upstream remains active (October 2026 maintenance); sampled open issues concern parseTree, formatting, trailing-comma defaults, bigint and bundling. The old stable release is not itself evidence of abandonment. [MSRC reporting policy](https://github.com/microsoft/node-jsonc-parser/blob/main/SECURITY.md) is present. Updating this parser requires strict-syntax, duplicate, number, prototype and worker-budget regression checks.

**Applicability restriction:** upstream [PR 140](https://github.com/microsoft/node-jsonc-parser/pull/140) fixes `parse()` assigning `__proto__` in a returned object's prototype; that fix is absent from 3.3.1. A controlled published-package probe reproduced this behavior. This application must never call that API. Published `visit()` scans tokens and invokes callbacks; inspection confirms it does not call `parse()` or assign input properties into constructed objects. The probe observed decoded `__proto__` and repeated names through the visitor without modifying prototypes. Use only `visit`, throw on every syntax error, reject duplicate/prototype/constructor keys, then use native `JSON.parse`. Its permissive recovery, comments and trailing commas must be explicitly disabled/rejected. This is a narrow API applicability assessment, not a general safety claim about 3.3.1.

Fastify open issues were sampled: #7166 late onClose registration, #7043 dual-stack drain, #7090 multiple async onSend hooks, #7098 encapsulated not-found routing, #7038 empty bodies, and response/serializer issues. Register lifecycle hooks before ready, use no dual-stack/custom router options or web Response handlers, and test empty-body rejection. Future composition must reassess these constraints rather than infer they are fixed.

**Additional reproduced applicability restriction:** a native HTTP POST to unmodified Fastify 5.12.8 with `handlerTimeout: 1000` produced `raw.complete=true`, `raw.aborted=false`, but `request.signal.aborted=true` after the normal body completed. The published `lib/route.js` treats every request `close` as cancellation and clears its timer. Open [PR 7047](https://github.com/fastify/fastify/pull/7047) addresses this exact behavior; [PR 7069](https://github.com/fastify/fastify/pull/7069) covers related lazy-signal/response-disconnect cases. No upstream patch is vendored or forced into the lock. This application therefore does not use Fastify's `handlerTimeout` or `request.signal` APIs. Its own ten-second operation deadline and signal observe request abort and response close/finish, retain the deadline after successful upload, terminate parsing on cancellation, and fence late results using monotonic time. Route registration rejects `handlerTimeout` overrides. Native socket tests require successful valid POSTs, expiration after a completed upload, and no effect after disconnect. This exclusion must remain until an upstream correction is freshly reviewed; enabling the faulty APIs is not authorized by the package selection. The raw server's header/receive/idle deadlines also remain enabled.
