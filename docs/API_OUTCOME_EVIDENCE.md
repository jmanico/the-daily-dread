## Implemented contract

`src/contracts/http-results.js` is a browser-compatible vocabulary and pagination contract without authentication, I/O or DOM capabilities. All existing HTTP error paths now use the same stable codes, messages, server request ID and field-error envelope. Registered routes receive the common error schemas. Statuses cover 200 read/update/existing, 201 create, 202 queued/running job references, 400 malformed, 401 authentication, 403 role, 404 unavailable scope, 409 revision conflict, 422 fields, 429 rate limit and closed 5xx failures. An uncertain effect has its own 502 code and directs the client to check status; this layer never retries or creates another effect.

`createOutcomeResponder` requires a reviewed resource schema and a synchronous explicit projector. The schema must close the root object and require its ID. Each future owner must also review/close nested fields, bound strings/arrays, choose units and enforce the complete per-workflow contract; this helper does not make an arbitrary supplied schema safe. Imported/user schemas must never reach this composition API. Projectors construct permitted fields, then actual strict Fastify validation rejects invalid/extra output before the response serializer. This prevents relying on a serializer silently dropping an accidentally returned private column. Plain-data checks reject accessors, executable/custom-prototype values, unsafe numeric integers, malformed strings and excessive nesting/entries. These checks are not a sandbox for hostile JavaScript supplied by a developer.

The translated response is copied before an asynchronous final authority check, so mutations of a shared owner/projection record cannot alter the approved snapshot. Scoped authority is required before projection and again immediately before disclosure. The callback receives the application's cancellation signal and must cancel its own I/O; operation expiry/disconnect fails closed. Business effects and database commits still require the owning use case's earlier authorization and atomic fences. Error field names must come from the configured public allowlist, never arbitrary provider messages or submitted values.

Pagination normalizes lexical strings explicitly: 50 by default, 1–100 accepted, no coercion of numbers/arrays/signs/exponents/leading zeroes. Optional cursors are bounded opaque URL-safe strings, not authority; the future owner must generate/bind them and perform a scoped query on every page. The dedicated query schema rejects repeats/unknown fields. A workflow with filters must declare those fields in its own closed query schema and pass only the validated pagination properties to this helper. Lists cannot exceed the declared page limit; empty/next-page metadata must be explicit. The presenter never fabricates an existing resource, deduplicates registrations, assigns a job or infers completion: it only translates the owner's typed outcome.
