## HTTP diagnostic capture follow-up

The production application factory now configures its existing Fastify/Pino logger with a capability-checked snapshot path. Automatic raw request/error calls, arbitrary messages and objects are suppressed before Pino examines their properties. Root process/hostname fields are disabled. Child bindings and `setBindings` are blocked before serialization: inspecting the installed Pino implementation showed that its child path resets the binding formatter, so a root formatter alone was insufficient. No library was added. This is a guarded logger instance, not a malicious-JavaScript sandbox.

HTTP method, registered code-owned route template and generated request identity are snapshotted before the access owner or handler runs. A completed response adds its actual status and monotonic duration. Connection cancellation produces `http_aborted` with no invented completion status. Native framing/expectation failures have only a generated request ID, fixed category and status; no raw packet, socket address or request object is retained. Route templates are restricted to bounded code-owned ASCII path syntax. Caller headers cannot set request identity; unknown paths are `unmatched`. These operational records are not `dread.*` security events or a claim of audit commit.

Encoding uses Pino's actual output bytes. Immutable validated snapshots alone enter that path. Code-owned bound INFO/WARN/ERROR methods survive later ordinary level changes. The capture holds at most **32 records / 128 KiB**, with a **4 KiB encoded-record ceiling**. Saturation increments a bounded drop counter and does not fail or block an HTTP operation. `take()` removes one immutable encoded string; `status()` returns only counts. The current narrow field maxima stay below the byte ceiling; tests exercise the reachable record-capacity boundary, not a fabricated 4,097-byte valid snapshot. This is an in-memory composition interface; stdout transport, its access controls, independent consumption and crash-loss detection remain separate work.

Nine focused groups pass against real Fastify and native loopback sockets: normal output, secret-bearing bodies/headers/URLs, forged request IDs, raw exceptions/causes, accessor and child-binding suppression, required INFO method retention, parser/schema/media/size failures, authorization denial and owner/handler errors, unknown paths, queue saturation/re-admission, invalid capture/snapshot inputs, malformed native framing, concurrent request isolation, post-snapshot mutation and client cancellation. Consumer tests parse the actual encoded JSON and reject secret canaries. Strict checked contracts, runtime/import guard, build/artifact, dependency graph, npm audit and whitespace checks pass. The final combined local suite passes **99 tests**, with no failures or skips. Selected-Linux CI results belong to the PR's exact tested revision.

## Still incomplete

The event projector does not authenticate context or establish company/role/revision authority. A syntactically valid reference is not authorization; a malicious developer-supplied Proxy is not sandboxed. The new HTTP capture is operational telemetry, not the authoritative audit destination. Security-event INFO delivery, PostgreSQL persistence/deduplication, atomic mutation/audit commits, independent health monitoring and crash recovery remain unimplemented. No runtime ledger row is promoted and Wave 0 has not passed. Actual security-event producer/consumer, authority, cancellation, PostgreSQL and failure tests named by #106 remain required as their owners are implemented. No later-wave instrumentation is enabled.
