## Implemented scope

The composition factory has no installed business routes, identity provider, listener or database. It requires a trusted coarse-access owner. Production handlers must still pass validated context to the authoritative use case and enforce current object/property scope, revision and commitment fences. Test-only registered handlers exercise the actual factory and parser with synthetic access decisions. These doubles do not establish production authentication or transaction invariants.

The factory fixes the SEC-3 strict Ajv options and prototype flags. JSON uses the reviewed token visitor before native object construction, in at most two process-wide workers with no pending-body queue. Limits: 64 KiB input, depth 64, 100,000 entries, two-second deadline and 64 MiB old-generation heap per worker. Raw UTF-8, syntax, duplicate decoded names, prototype keys and decimal precision loss are rejected. Native number round-trip equivalence does not claim binary floating-point exactly represents arbitrary decimals. Identifiers still require the owning schema's exact representation. Workers receive only bytes, no service environment or inherited preloads. Cancellation owns worker termination and cleanup. Container memory limits and installation-wide coordination with future parser/PDF owners remain necessary.

Query parsing retains repeats, rejects malformed percent/UTF-8 and prototype keys, and caps 4 KiB/100 occurrences before route cardinality/schema validation. Object schemas must close writable fields; string/array limits are route-owned. The factory accepts only JSON/UTF-8 commands, disables compression and rejects duplicate headers, trailers, ambiguous framing and excess header count. Node uses strict framing, 16 KiB headers, 10-second header/30-second receive/30-second idle deadlines, five-second keep-alive, 100 requests/socket and 200 accepted sockets. These finite settings are not measured capacity evidence.

Application-owned ten-second deadlines survive normal upload completion and cancel on actual disconnect. `operationSignal(request)` must be passed to the use case/adapters and checked again before effects; a timer alone does not roll back an arbitrary handler. Fastify's faulty signal/handlerTimeout APIs are excluded, not used as deadline enforcement. Safe error projections cover route, framework malformed-URL/max-parameter, and native framing paths. A real test caught Fastify's default malformed-URL input reflection; the replacement returns no URL/error text. No raw request/error logger is enabled pending the required Wave-0 integration. That absence is an outstanding observability requirement, not audit acceptance.

## Actual verification and remaining gates

Local Node 24.16.0/npm 11.16.0/macOS arm64: eight new test groups exercise registered parsing/schema/access boundaries and actual TCP framing. Positive native POST and exactly 100 headers succeed; 101 headers, conflicting lengths/transfer coding, duplicate credentials, oversized headers/chunked bodies, expectation/trailer misuse and malformed chunks are rejected without additional effects. Negative tests cover unknown fields (not stripped), missing defaults, string booleans, duplicate nested/escaped keys, prototype names, depth/byte boundaries, precision loss, invalid UTF-8, unsupported encoding/media, repeated query fields, denied/failed access and safe canary errors. A completed native upload still reaches the ten-second operation timeout; the handler cannot perform its late effect. Worker tests cover admission, cancellation, monotonic expiry while the event loop is blocked, and successful slot reuse. Client disconnect during authorization prevents the handler.

Local build, strict types, runtime/import guard, dependency/artifact policy, all 45 tests, audit (zero known advisories) and whitespace checks passed. Selected Linux CI is pending for this draft.
