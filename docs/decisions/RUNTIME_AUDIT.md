# Runtime audit selection

Decision: REQ-DECISION-015 / TOOL-003 ([#26](https://github.com/jmanico/the-daily-dread/issues/26)), 2026-11-05. Accountable project owner: Jim Manico, who delegated resolution of blocked decisions. The release maintainer owns execution on every release runtime. Applies to NFR-4, NFR-5, SEC-1/SEC-5/SEC-6/SEC-9/SEC-10, TB-10 and the REQ-PLATFORM-022 build checks (#104).

Select `node scripts/audit-node.mjs`, with exact locked development dependency `semver` 7.8.6. The [NFR-5 review](../DEPENDENCY_REVIEW.md#runtime-audit-alternative--2026-11-05) covers its direct use. Keep the rejected `is-my-node-vulnerable` candidate and forced transitive overrides out of the tree. This is a narrow local build check, not a replacement package for general vulnerability scanning or an application source connector.

The checker downloads the official [Node security working-group core advisory database](https://github.com/nodejs/security-wg/blob/main/vuln/core/index.json) and [Node release schedule](https://github.com/nodejs/Release/blob/main/schedule.json). These are the sources used by the [Node-owned runtime checker](https://github.com/nodejs/is-my-node-vulnerable). It evaluates its actual `process.version`, rejecting caller arguments, prereleases, unknown or unsupported release lines. A version matching an advisory's vulnerable range without matching its patched range fails the gate. All severities and platform-specific records are considered conservatively; there is no exemption list.

Native verified HTTPS requests use two fixed URLs, no credentials, redirects, cached fallback or configurable destinations. Each download has a 10-second total cancellation deadline; security data is capped at 2 MiB and the schedule at 256 KiB. Only HTTP 200 and uncompressed content are accepted. HTTP Date/Age checks reject responses older than 24 hours or more than five minutes in the future. This checks transport freshness, not whether upstream has published every vulnerability. Source hashes identify the exact bytes evaluated and are not signatures or proof of completeness.

The existing bounded worker parses JSON with depth 16, 100,000 entries and a two-second task deadline; malformed UTF-8, duplicate keys and forbidden prototype keys are rejected. Advisory counts are bounded at 5,000 and each range at 256 characters. Strict vetted SemVer validation precedes comparison. Evaluation also checks a two-second elapsed budget between bounded comparisons. The five-minute CI job timeout provides a separate process-level ceiling including installation. No claim is made that an in-process elapsed check can interrupt one synchronous comparison.

Unavailable sources, malformed or empty data, truncated/oversized bodies, source errors and unsupported runtime versions exit nonzero. Raw downloaded text and exception content are excluded from diagnostic errors. Successful retrieval prints the checked runtime, record count, matching IDs/CVEs and patched ranges, checked time and source hashes; matching advisories still exit nonzero. A zero result means no match in the fetched database at that time, not proof of safety.

## Validation and remaining gates

The dedicated tests exercise affected and patched versions, platform/severity conservatism, invalid ranges/identifiers/dates, support expiry, destination rejection, real loopback socket bytes, redirects/errors/encoding, missing/stale/future response dates, stale Age, declared/chunked size excess, hanging/truncated connections, worker parsing failures, setup exception redaction, invalid budgets and rejected CLI overrides. No private credentials or application data are fetched.
