# Local credential lifecycle — REQ-LOCAL-011 (#254)

2026-11-05, Node 26.13.0/npm 11.20.0, macOS 27.2 arm64. This implements the PostgreSQL credential owner for LOCAL-1. It does **not** activate private routes, issue a credential on Jim's machine, replace the live public demo, or establish complete authentication/audit coverage. Only disposable synthetic PostgreSQL fixtures were migrated.

The trusted composition supplies fixed workspace, actor and configuration-revision UUIDs. Bootstrap selects a fresh process generation and clears previous sessions/codes; it cannot replace an existing actor or revision. The launcher must validate the actual workspace and obtain exclusive listener ownership before calling bootstrap. That orchestration remains unimplemented. Browser input never selects these references or calls bootstrap/code issuance/activity directly.

Native Node crypto supplies separate 32-byte launch and session secrets. Canonical base64url validation precedes purpose-separated SHA-256; only digests enter storage, and fixed-size comparisons use `timingSafeEqual`. The owner returns a raw credential only after acknowledged transaction commit and the final cancellation/time check. Neither returned errors nor identity projections include credentials, digests, SQL or database errors. Secrets in JS memory are not claimed to be securely erasable.

Every operation locks the workspace authority row in the existing scoped SERIALIZABLE transaction. Code replacement, five failed attempts in a rolling minute, atomic consumption, an eight-session ceiling, expiry, activity and logout share that boundary. The owner admits at most two concurrent operations with no waiting queue; database connection/lock/statement bounds remain those of the existing transaction adapter, with a three-second owner deadline. Serialization conflicts are explicit results, not hidden retries. An uncertain commit closes this owner permanently; a new owner/process generation is required. A credential withheld after a late commit is never recovered or retransmitted; any inaccessible session remains bounded and expires or is cleared by restart.

Both wall time and monotonic elapsed time enforce 60-second codes, 30-minute idle expiry and eight-hour absolute expiry. Verification/polling does not update activity. A distinct trusted activity capability may update activity only after the actual user operation's authorization; this is not an HTTP-selectable flag. A rollback/invalid clock closes admission and aborts in-flight work. Generation and actor/revision checks reject stale state; `stop()` immediately fences this owner even if storage is unavailable. This is not platform clock-anomaly telemetry or restoration acceptance.
